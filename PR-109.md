_Requested by **Guy**_

Third filter test PR, stacked on the matching PR (merge that first): the edit flows, end to end.

**Tests (`filter-flows.test.ts`):** the real store runs against a fake folder and game, and each result is checked by parsing what was written. Hide, restyle and pin for every item at three strictness levels, every move in every group, every tier edit, saves, reloads, sources, and regressions for the wrong-base and deferred-reload bugs.

**Bugs found and fixed**
- Rules with no `$type`/`$tier` tags (FilterBlade's conditional entries, anyone else's filter) couldn't be edited or searched. They're now keyed by their conditions.
- An own rule copied the first block of its tier, so it could miss the item it was made for.
- A rare and a magic of one base folded into a single own rule.
- An own rule stayed below its item after the item moved to a higher tier.
- Moving a base took it out of all its stack tiers, not just the one moved.
- A tier commented out for being empty couldn't take an item.
- Always show could still be caught by an earlier rule. It now goes above everything.
- Two quick saves raced for one temp file. They now run in turn.
- Replacing a filter the game has open fails on Windows. It now retries for a moment.
- The update check counted safety-net changes as not fitting.
- Opening our copy of an online filter now finds the online one when it's still there.
- A sound with no volume read as 300; the game's defaults are 50 and 100.

Local checks: typecheck, lint, all unit tests pass.

_Requested by **Guy**_

Fixes WOKEPOET-43, WOKEPOET-44 and WOKEPOET-58, from the [overlay core critique](https://claude.ai/artifact/Du1efrqGyeBo1LyyHQHtTw).

## Why

- "Change saved" only updated memory. The file was written when Settings closed, and `saveConfig` refuses while Settings is open. Quit from Settings, tray Quit, Restart now, a crash or a power cut all lost the changes.
- A damaged or empty `config.json` loaded defaults with no message. Later saves went to `config.json.tmp`, so that session's changes were lost too. No backup, no flush to disk, and a failed write quit the app.
- A config from a newer version had no guard, and a throw in `upgradeConfig` left the page blank.

## What changes

**Saving**
- Each Settings change now writes to disk with a quiet save, which doesn't echo back (the echo would close Settings). The file never records a popup as open.
- `before-quit` asks the page to save, waits up to 500 ms for its answer and up to 2 s for the write, then quits. Covers Settings, the tray and Restart now, and can't hang the quit.

**Damaged files**
- `config.backup.json` is refreshed on the first write of a run, so it holds the settings from before any upgrade, then at most every 30 minutes. Only valid files are copied.
- A damaged or empty file becomes `config.broken-<time>.json`, and the backup takes over.
- A file that can't be read right now (antivirus, sync tools) gets a few retries. After that it's left alone, and this run's saves go to the temp file instead of replacing it with defaults.
- Writes flush to disk before the rename. A failed write is logged, and the next one retries.

**Versions**
- A newer config or a failed upgrade keeps the file untouched, and this run saves to the temp file.

**Notices**
- The existing notice pill says what happened in each of these cases.

## Testing

`config-store.test.ts` and `config-for-disk.test.ts` are new. Typecheck, lint and unit tests ran locally. The quit flow wasn't run in the packaged app or in game.

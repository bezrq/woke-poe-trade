_Requested by **Guy**_

Fixes WOKEPOET-40 and WOKEPOET-42, from the [overlay core critique](https://claude.ai/artifact/Du1efrqGyeBo1LyyHQHtTw).

## Why

[GGG's macro rules](https://www.pathofexile.com/developer/docs) say macros must be invoked manually, and name timers and reacting to file changes as not allowed. The loot filter sent `/itemfilter` 4 s after a Client.txt area line, in two cases: a held reload, and a strictness ladder switch.

Separately, chat commands could wait up to 30 s for a typing pause and then type with no focus check, so another app could receive Enter, Ctrl+V and Enter.

## What changes

- A log line or timer never sends a command. The ladder still saves the file, then says to press Reload now.
- Entering town or a hideout with a held reload shows a reminder toast instead of sending.
- Clicks and hotkeys still send: Save + reload, Reload now, and a quick fix made in town.
- Commands from the overlay check that the game really has focus (Windows' report, not our own flag) and wait until it does, up to 600 ms. If neither game nor overlay has focus, they're dropped with a log line. Stash search now gets the same settling time as chat.

## What players will notice

Filter changes from the ladder no longer apply by themselves. A better prompt than a toast needs mocks first (follow-up on WOKEPOET-40).

## Testing

Updated `filter-flows.test.ts`: a held reload never sends, even a minute after entering a hideout. Typecheck, lint and unit tests ran locally. Focus behaviour in `Shortcuts.ts` has no unit test and wasn't run in game.

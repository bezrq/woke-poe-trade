Step 3 of [Moving off Electron](https://claude.ai/artifact/PsvGcVErmMx1HPePhViXyt). This is a draft and a throwaway: it exists to answer "does the overlay work on Tauri over PoE, and what does it save?" before we commit to a port. It is not meant to merge as is.

## What it is

`spike/tauri-overlay/` is a small Rust app (Tauri 2) that:

- serves the **unchanged** built overlay (`renderer/dist`) and speaks the same `/events` WebSocket protocol as `main/src/server.ts`, so the Vue code runs as is inside WebView2
- keeps a transparent, click-through, topmost window over the game's client area. It follows the game with WinEvent hooks (foreground, location, destroy, scoped to the PoE process) and hides when neither the game nor the overlay has focus
- hands focus back and forth on Shift+Space and Esc (AttachThreadInput + SetForegroundWindow, no fake Alt press)
- registers the config's global hotkeys; item copy works through SendInput Ctrl+C and clipboard polling, the same as HostClipboard.ts
- runs dock hover zones and dwell-to-activate through a low-level mouse hook (the same logic as `main/src/woke/hover.ts`)
- proxies trade and poe.ninja requests like `proxy.ts`
- logs the memory of its whole process tree every 15 s, viewable from tray > Show test numbers

Not included: OCR scans, the in-overlay browser (`<webview>`), Client.txt, file-based woke handlers, the updater. The test answers those requests with a clean error.

## CI

`.github/workflows/tauri-test.yml` (Windows) builds it and uploads the **woke-tauri-test** artifact (exe + web/ + README). It then starts the Electron app and the Tauri test on the same runner and puts both memory totals in the job summary.

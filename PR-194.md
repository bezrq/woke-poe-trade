_Requested by **Guy**_

## What

Guy's dev overlay got stuck behind Vite's "URI malformed" error screen. Esc didn't close it and it had no close button, so he had to quit the app. This only affects dev mode.

- `server.hmr.overlay: false`, so Vite's error screen can't cover the game overlay. Errors still go to the log and the console.
- A small dev-only plugin answers a request Vite can't decode with a 400 and logs the URL and referer. Proxied paths skip it, because they go on to the app, which reads them fine.

## Not fixed

**The bad address itself isn't found.** Vite's error doesn't name it. A headless run through Uniques > Replicas, including hovering Simple Robe where it showed, requested nothing undecodable, though it ran the built app, not dev. The next one writes the URL to `E:\Git\.woke-dev\vite.log`.

## Also

`loot-filter.spec` used a Debeon's Dirge locator that now also matches the item tip; it takes the first match.

## Checks

Against a spare dev server on port 5199: raw `%` in a path and a query gets 400 and a log line, normal files and `/` get 200, and a proxied URL with a raw `%` passes through. Typecheck and build pass, and the item-tip and loot filter e2e specs pass (16).

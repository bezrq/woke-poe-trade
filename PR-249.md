_Requested by **Guy**_

A pull request that only touches the website no longer runs the app's tests. A new `What changed` job reads the PR's changed files, and the two required checks skip their work when nothing they test changed.

| Files changed | Unit tests, lint, types | Fake-game tests |
| --- | --- | --- |
| `docs/`, `testing/e2e/landing-*.spec.ts`, `testing/fixtures/screens/frames/`, `testing/fixtures/lab-layout.jpg` | skipped | skipped |
| `README.md` as well (a unit test reads its module table) | runs | skipped |
| Anything else | runs | runs |

- **Why not a path filter:** both checks are required on master, and a check that never reports blocks the merge forever. A job skipped by its `if` reports as passed.
- **What can't slip through:** pushes to master always run everything, so a landing spec that doesn't compile would still show up there. If `What changed` fails, can't read the file list, or the list hits GitHub's 3000-file limit, both checks run in full.
- **Job names are unchanged,** so the ruleset still matches.

Checked: the decision logic on sample file lists, and the YAML parses. This PR runs everything because it changes the workflow itself, so the skip isn't proven yet. The next site-only PR tests it: the landing cleanup follows straight after this, and if the skip doesn't count as passed there, this gets reverted.

_Requested by **Guy**_

## What was wrong
- **Badge in an empty cell:** the scanner took the cursor from uiohook mouse moves. uiohook-napi has no drag event, so moves with a button held were never seen, and the badge and marker stayed at the old position.
- **Rolling stuck after moving on:** rolling mode kept watching the box locked on the first tooltip, so another map or stash tab (such as a quad tab) read nothing.
- **Quad neighbours:** the same-slot radius was about one quad cell wide, so hovering the next map counted as a reroll.

## Changes
- Read the OS cursor on every scan frame instead of listening to mouse moves.
- Drop the roll lock once the cursor moves more than about one quad cell from where it locked.
- Measure same-slot distance in real pixels, at half a quad cell.

## Testing
- New e2e tests: dragged cursor and rolling onto another map. The rolling test fails without the fix.
- Map and essence scan e2e, OCR tests, tsc, vue-tsc and eslint pass.
- Quad tab not tested on a real capture: a simulated quad grid still read the tooltip correctly.

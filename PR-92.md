_Requested by **Guy**_

Picking a loadout chip in the PoB panel only changed that panel's view. Now the pick is saved per build and every window reads it.

- **Reads the pick:** Links you need now and its regex, Gems by level, the Gear and Setups tabs, the campaign card and dock card (in-town gems, quest rewards, links, tree), the price chip, and the filter rules.
- **Saved as:** `loadouts` on the PoB widget, by set title, so reordering sets in PoB doesn't break it. A renamed set falls back to the level-based pick.
- **Same-named sets move together:** picking a skill set also takes the item set and tree with that title. Picking a different item set on Gear keeps the skill set, for mixing.
- **Default unchanged:** the level-based pick applies until a chip is clicked. `· now` always marks the set in use, a pin marks a hand pick, and the Auto chip (or clicking the pinned chip) goes back to following level.

**Left whole-build on purpose:** the price chip's "In your build" and the filter's gem and unique lists still cover every set in the build, so a later loadout's unique isn't hidden. Rare bases, weapon classes and link colours follow the pick.

**Tests:** new unit tests and two new e2e tests (campaign card, saved config, Auto, price chip). `pob-builds`, `campaign`, `price-check` and `loot-filter` e2e specs and `renderer/test/woke` pass, `vue-tsc` and `eslint` are clean. `toolkit.spec.ts` stops the whole e2e run at load time with a `MODULES` import error, in a file this PR doesn't touch, so I ran specs by name.

May conflict lightly with WOKEPOET-17 in `BuildDetail.vue`.

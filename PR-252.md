_Requested by **Guy**_

Closes a gap in #249 found in its review: a PR changing only `testing/e2e/landing-*.spec.ts` skipped both checks, so a landing spec that doesn't compile could merge green and then break the next app PR's fake-game tests.

When a landing spec changes, `What changed` now runs `npx playwright test --list e2e/landing-`, which takes a few seconds. If that fails, the job's outputs stay empty, so both required checks run in full and fail on the spec. Failing `What changed` alone wouldn't block the merge, because it isn't a required check.

This PR touches a landing spec's comment on purpose, so the new step runs here on a fresh install. It also changes the workflow, so the full tests run too.

Checked: `--list` fails with a non-zero exit on a spec with a syntax error. On this PR the step passed on a fresh install, and an earlier push where it failed sent both required checks into their full run, as intended.

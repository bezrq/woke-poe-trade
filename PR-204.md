_Requested by **Guy**_

## Summary

Stash outlines didn't work on Guy's other stash, whose Scarab tab has an extra Breach button. That moved the SCARAB text the reader used as its marker, so it reported "can't read this tab". That stash also holds different scarabs in some slots. Guy also saw toasts cut off with an ellipsis.

- **Marker:** now the row symbols at the left of the tab, which stay put. Across Guy's 47 screenshots they scored 0.99 or more on the 3 Scarab tab shots and 0.48 or less on the rest.
- **Layouts:** the two known stash layouts each have a slot table, chosen by where the SCARAB text sits. An unknown layout draws nothing.
- **Filled slots:** decided by how blue a slot's corners are relative to their brightness, so a darker screen keeps the same split.
- **Toasts:** long text now wraps, for every toast in the app, and the outline's "can't read" note is shorter.

## Limits

- Only these 2 layouts are handled. Another button arrangement reads as "can't read this tab".
- If a stash keeps the button position but holds different scarabs, the wrong table would apply with no warning. There is no check for that.
- On the Breach layout, the filled slots at (184,298) and (184,361) have no name, as no icon matched, so they get no outline.
- Slot names are spot-checked by eye, plus a few asserted in tests. Some Breach-layout names rest on weak icon matches.
- A tooltip over the row symbols makes the read fail. The new markers are larger than the old one, so more mouse positions cause this. The note says to keep the mouse off.
- Not checked in the real app.

## Testing

- `testing/vision/stash-read.test.ts`: named slots on the Breach layout, a darker screen, both layouts at 720p. 9 passed.
- Unit tests, type checks and the flips fake-game tests pass locally; the rest of the fake-game suite was not run.

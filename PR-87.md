## Summary

Current rolls on map stats no longer sends a max of ~9e15, which the trade site rejected with `Invalid map_iiq max value`. Those stats have a `MAX_SAFE_INTEGER` placeholder as their upper bound, and the preset took a window of it.

```diff
 presetRange(roll, 'current')
+  if bounds are the open-ended placeholder
+    return this roll or better, other end empty
   window = 10% of (bounds.max - bounds.min)
   return roll ± window, clamped to bounds
```

The roll bar now takes both buttons, in every mode. It used to ignore clicks once both ends were set.

```diff
 StatRollSlider.handleMousedown
-  if mode is not min or max: return
-  edit whichever end the mode has
+  left button: edit min, right button: edit max
+  other end kept, unless the new value crosses it (then cleared)
```

## Evidence

- **Before:** `Current rolls on a map searches from each roll up, with no max` fails: `expected { value: 87, min: +0, … } to match object { min: 87, max: undefined }`
  **After:** `renderer/test/woke/roll-controls.test.ts` 6 of 6 pass, full suite 167 of 167 pass, `vue-tsc` and eslint clean.
- **Roll bar**, real `FilterModifier` in Chromium with bounds 20 to 40, starting at 28 to 32:
  - Right-click at 75%: 28 to 35, max box focused, no context menu.
  - Left-click at 25%: 25 to 35, min box focused.
  - Left-click past the max: 38 and up, max cleared.
  - Right-click below the min: up to 22, min cleared.
  - Middle button: no change.

Not checked: a live search against the trade site. The test stops at the filter's min and max, so the request itself was not sent.
